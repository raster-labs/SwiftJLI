# Round 4 experiment archive

This directory preserves the investigations that informed the round 4 implementation, including rejected variants and initial failures. It contains text evidence only. Final integrated tests, oracle checks and comparisons with djpeg belong to the parent qualification report.

The starting revision was `8ae2762710d6279cd92222f5bb5ca95f042f694e`, whose production implementation was `5351088d3bb4630a32de6509e4d62210ad14aaa0`; suite policy was **0.10.0**. [Source pins](source-pins.json) records full child and integrated commit identities. [Inventory](inventory.json) maps every copied artifact to its original absolute path, byte count, SHA256 and source-file modification time. Copies preserve the original bytes, including historical wording and external paths. Original evidence indexes also retain hashes of external binaries and fixtures; those files are excluded from this archive.

## Measurement boundaries and chronology

These are investigation receipts, not interchangeable final-source benchmarks. Each JSON retains its own runner commands, fixture identities, object/binary hashes and options where recorded. The DCT [original evidence index](dct/swiftjli-round4-dct-evidence-index.json) supplies command lines and links the stages. Its default native harness uses **eight workers**; the separate one-worker harness explicitly changes that ceiling. The initial direct-output default-harness run therefore did not exercise the large-image single-worker path. Both runs are retained.

The DCT RSS scripts measure a native process that performs one checked decode plus 25 warmup/measured decodes, over three ordered repeats. They measure whole-process peak RSS, not isolated workspace or CLI RSS. For example, the accepted explicit-one-worker streaming experiment measured DCT12_2048 at 120,619,008 versus 46,596,096 bytes, a 61.4% reduction. This is an explicit-one-worker result. Large default decodes retain full coefficients/component planes with bounded reconstruction scratch.

Later grouped-window, scalar512 and three-way timings are **provisional**. The user authorised collection while a foreign Virtualization VM remained active; observed snapshots included roughly 400–474% CPU. Exact-output checks remain valid. Earlier experiments used coordinated local CPU slots, but this archive makes no blanket claim of host quiescence. Raw samples, outliers and rejected continuations are retained. [Annotations](annotations.json) identifies the timing phases and the limits of the host observations. Embedded execution timestamps are authoritative where present; filesystem modification times are only file metadata.

The rejected patches are working-source snapshots, including minor documentation/selector changes between builds. They are not final production revision pins. The measured object and executable hashes remain in their benchmark JSON. Reused harnesses are archived under [support](support); their original absolute paths are intentionally preserved in the raw receipts. Reproduction requires supplying the matching externally pinned products and fixtures.

## Ownership probes and failed attempts

The [Span probe](ownership-probes/swiftjli-round4-span-probe.swift) was rejected under ordinary compiler feature support; no experimental flags were adopted. Its standalone diagnostic stderr was not retained separately.

The initial [NSData probe](ownership-probes/swiftjli-round4-nsdata-probe.swift) exercised snapshots, slices, COW and lifetime under explicit pools. The subsequent [release investigation](ownership-probes/swiftjli-round4-nsdata-release-probe-results.txt) found 0/32 immediate releases without a surrounding pool; pooling bridge/factory creation alone was insufficient. Pooling pointer acquisition produced 32/32 immediate releases and was an intermediate solution. The final [CFData pointer probe](ownership-probes/swiftjli-round4-cfdata-pointer-probe-results.txt) demonstrated 32/32 immediate releases without a pool, with retained immutable owners and normal toll-free casting. Its historical statement that production remained unchanged describes the probe's execution point, before root integration.

Initial failure receipts are retained: the [Data-reader compile failure](input-reader/data-reader-tests.log) and [successful retry](input-reader/data-reader-tests-retry.log); the [admission-test macro failure](input-reader/streaming-admission-tests.log); the CLI [descriptor-flag assertion](cli/cli-tests.log), [shadowed-variable failure](cli/cli-tests-final.log) and [verified report](cli/cli-tests-verified/report.json). The ownership release-results text records its initial exit-133 probe defect and subsequent correction.

Some temporary log paths were reused before archival. [Annotations](annotations.json) explicitly records these gaps, including the DCT harness argument-order compile error and the initial CLI2048 memory-budget rejection. Those notes are reconstructed session outcomes, not replacement raw stderr. No failures were rerun for this archive.

The ownership portability patch preserves universal snapshot, owner-range, byte, release and joined-read checks while limiting original-Data pointer-identity assertions to Apple platforms. These standalone probes qualify their recorded macOS/Swift toolchain only; Linux and minimum-OS runtime coverage are not implied.
